## Shipped this session

### 1. AI catalog-mismatch guard (`lib/ai/catalog-guard.ts`, `app/api/cron/ai-catalog-guard/route.ts`)
Closes the "AI replies aren't checked against the real product catalog" gap noted in the 2026-07-01 closure report. Deliberately **not** wired into `app/api/whatsapp/incoming/route.ts` (the send-adjacent hot path) — a synchronous per-message DB+regex check there adds latency and a new failure surface to every inbound message for every tenant, and CLAUDE.md requires explicit approval before touching that pipeline. Instead: hourly cron scans `Message` rows with `role: "assistant"` from the last 65 minutes, extracts price mentions, compares against each tenant's active `Product` catalog, and writes a `SafetyAudit` row (`category: "ai_catalog_mismatch"`) for mismatches — surfaced automatically on the existing `/dashboard/safety` page (its API has no category filter, so no UI change was needed). Dedupes against re-scans of the same message via a payload-substring lookup.

**Bug caught by functional testing, not caught by typecheck/build:** the price regex originally ended in `\b`. JS `\b` is defined against ASCII `\w`, so it never matches at the end of an Arabic word — every match against real Arabic price phrasing ("999 جنيه") silently failed, and the guard would have shipped completely inert. Fixed by replacing `\b` with a lookahead for whitespace/punctuation/end-of-string. Verified with seeded data: hallucinated price (999, no matching product) → flagged; real catalog price (150, matching a seeded product) → not flagged; re-run of the cron over the same message → no duplicate flag.

**Not yet wired into production scheduling** — the hourly dispatcher (`/home/ubuntu/run-hourly-crons.sh` on the AWS box) is a hand-maintained script, not tracked in git. `ai-catalog-guard` needs to be appended to its endpoint loop after this deploys (see Deploy section).

### 2. Invoice model + PDF generation (`lib/invoices/generate.ts`, `app/api/invoices/[transactionId]/route.ts`, `Invoice` model)
Auth-gated, per-user-scoped PDF invoice download for paid `PaymentTransaction` rows. Idempotent — repeat downloads reuse the same `Invoice` row/number instead of creating duplicates. Surfaced on `/dashboard/wallet`.

**Bug caught by functional testing:** `pdfkit` resolves its `.afm` font-metric files via a `__dirname`-relative `fs.readFileSync` at runtime. Next.js's default webpack bundling of route handlers rewrites `__dirname` to the compiled `.next/server/...` output path, where the font data files were never copied — every PDF render 500'd with `ENOENT` in production-built mode (`next build && next start`), invisible in `next dev` and invisible to `tsc`/`next build` type-checking. Fixed by adding `pdfkit` to `experimental.serverComponentsExternalPackages` in `next.config.js`, which makes Next.js `require()` it directly from `node_modules` instead of bundling it, preserving correct `__dirname` resolution. Verified: real PDF (`file` reports `PDF document, version 1.3`) downloads successfully after the fix; 401 for unauthenticated, 404 for someone else's transaction.
