## The 60-second summary

**The application is fully reproducible from Git. The platform is not — yet.**

Three things are **not** in Git and have **no guaranteed off-site copy**, so a total VPS loss today is not cleanly recoverable:

1. **The production database** (`saas.db`) — backups exist but write only to the VPS's own disk.
2. **The secrets**, above all **`AUTH_SECRET`** — it decrypts every tenant's stored AI/Meta keys. Stored only on the VPS.
3. **The CloakBrowser LLM proxy source** (`main.py`) — the default AI engine, not tracked in version control at all.

**Verdict (full evidence in [FINAL_READINESS_REPORT.md](FINAL_READINESS_REPORT.md)):**
> **NO** — not reliably, as currently operated. Becomes a durable **YES** after three actions: (1) encrypted **off-site** backups of DB + sessions + `.env`, (2) secrets + DNS access in an **off-VPS vault**, (3) **commit the LLM proxy source**.

**Overall readiness: 52 / 100.** Completing those three actions raises it to ~80 and flips the verdict to YES.

## Key infrastructure facts (as found)

- **Host:** single Windows Server VPS, `217.154.163.16` (2 vCPU, 8 GB RAM, 128 GB SSD).
- **Services (NSSM):** `mse-saas` (Next.js :3000), `mse-wa` (whatsapp-web.js :7799/:3001), `mse-llm` (CloakBrowser FastAPI :7788), `mse-caddy` (:80/:443).
- **DB:** SQLite, `prisma db push` (no migrations dir), 64 models; `schema.postgres.prisma` ready but not cut over.
- **WhatsApp:** whatsapp-web.js (Puppeteer) is production; Baileys + Meta Cloud disabled by default.
- **Uploads:** none on disk — docs/media parsed to text into the DB.
- **Backups:** daily SQLite gzip (14d) + pre-deploy full snapshots + verification — **all VPS-local, no off-site.**
- **Deploy:** GitHub Actions builds an artifact → SSH/PowerShell → Windows VPS → NSSM restart (8–12 min outage). A Docker/GHCR/Watchtower Linux path is prepared (`docker-compose.production.yml`) but not in production.
